# Політика документації першого рівня

[en](../en/DOCUMENTATION_POLICY_L1.md) · [uk](DOCUMENTATION_POLICY_L1.md)

## 1. Нормативна мова

Англійська є основною та нормативною мовою всіх документів Aftertime першого
рівня.

Агент ПОВИНЕН використовувати лише англійську версію документа, коли він:

- тлумачить вимоги, визначення, межі або рішення;
- планує чи виконує роботу в проєкті;
- перевіряє сценарій, модель, процес або результат;
- усуває неоднозначність чи конфлікт між документами;
- створює похідні машинозчитувані артефакти.

Агент НЕ ПОВИНЕН використовувати переклад як нормативне джерело. Переклад можна
перевіряти лише для підтвердження наявності обов’язкового дубля та відповідності
ідентичності й ревізії канонічного документа.

## 2. Обов’язковий український дубль

Кожен англійський документ першого рівня ПОВИНЕН мати повний український дубль.

Український дубль призначений для україномовних читачів. Він ПОВИНЕН зберігати
зміст, структуру, ідентифікатори, числа, одиниці, посилання та ревізію
англійського канонічного документа, але НЕ ПОВИНЕН використовуватися Агентом
для тлумачення або виконання вимог проєкту.

Англійська та українська є єдиними мовами документації першого рівня. Матеріали
будь-якою іншою мовою не мають нормативної сили.

## 3. Розміщення файлів

Канонічні документи та переклади ПОВИННІ мати однакові відносні шляхи:

```text
docs/en/<relative-path>
docs/uk/<relative-path>
```

Приклад:

```text
docs/en/science/ACCOUNTING_RULES.md
docs/uk/science/ACCOUNTING_RULES.md
```

Машинозчитувані схеми та приклади, які виконує Агент, ПОВИННІ бути канонічними
в англійському дереві. Український дубль може містити перекладені
людиночитні значення, але НЕ ПОВИНЕН змінювати ключі, ідентифікатори, значення
переліків, одиниці, формули або поведінку перевірки.

## 4. Мовні коди ISO 639-1

Aftertime застосовує дволітерні мовні ідентифікатори, визначені стандартом
[ISO 639-1:2002](https://www.iso.org/standard/22109.html).

Підтримуються лише такі мовні коди першого рівня:

| Код | Мова | Роль |
| --- | --- | --- |
| `en` | англійська | канонічна й нормативна для використання Агентом |
| `uk` | українська | обов’язковий людиночитний дубль |

Мовні коди ПОВИННІ:

- записуватися малими літерами;
- використовуватися в метаданих документів, перемикачах мов, назвах каталогів,
  ідентифікаторах локалей і машинозчитуваних маніфестах;
- відображатися у фіксованому порядку: спочатку `en`, потім `uk`;
- замінювати текстові назви мов у перемикачах.

Кожен перемикач мов у Markdown ПОВИНЕН мати такий формат:

```markdown
[en](../../README.md) · [uk](../../README.uk.md)
```

Непідтримуваний мовний код або посилання не може з’являтися в перемикачі мов
документа першого рівня.

## 5. Обов’язкові метадані

Кожен документ першого рівня ПОВИНЕН починатися з YAML-метаданих:

```yaml
document_id: stable.lowercase.identifier
revision: 1
status: draft
language: en
canonical: true
translation: ../../uk/matching/path.md
```

Український дубль ПОВИНЕН використовувати:

```yaml
document_id: stable.lowercase.identifier
revision: 1
status: draft
language: uk
canonical: false
translation_of: ../../en/matching/path.md
```

Обидва файли ПОВИННІ мати однакові `document_id`, `revision` і `status`.

## 6. Правило синхронізації

Зміна англійського документа першого рівня не завершена, доки його український
дубль не оновлено в тому самому наборі змін.

Якщо український дубль відсутній, неповний або має іншу ревізію:

1. англійський документ НЕ МОЖНА переводити у статус `approved`;
2. Агент ПОВИНЕН повідомити `documentation_translation_out_of_sync`;
3. роботу можна продовжувати з англійським draft лише тоді, коли завдання явно
   дозволяє використання чернеток;
4. Агент НЕ ПОВИНЕН усувати розбіжність, вважаючи український текст
   авторитетним.

## 7. Розв’язання конфліктів

Якщо англійський та український документи відрізняються:

1. англійський канонічний документ визначає поведінку Агента;
2. український документ позначається як несинхронізований;
3. український переклад виправляється відповідно до англійського;
4. зміст англійського документа змінюється лише через звичайний процес
   перевірки, а не як неявний наслідок відмінності перекладу.

## 8. Умова затвердження першого рівня

Документ першого рівня може мати `status: approved` лише коли:

- канонічний англійський документ завершений;
- український дубль існує;
- ідентичність і ревізія метаданих збігаються;
- усі нормативні ідентифікатори, формули, значення й одиниці збігаються;
- локальні посилання працюють;
- потрібні машинозчитувані приклади проходять перевірку за своїми схемами;
- англомовна перевірка прийняла нормативний зміст;
- україномовна перевірка підтвердила точність перекладу.

## 9. Алгоритм маршрутизації Агента

Для будь-якого завдання з документацією першого рівня Агент ПОВИНЕН:

1. знайти потрібний документ у `docs/en`;
2. прочитати й застосовувати лише цей англійський канонічний зміст;
3. перевірити, що парний файл у `docs/uk` існує та має відповідні метадані;
4. виконати завдання на основі англійського джерела;
5. оновити обидві мовні версії, якщо документація змінюється;
6. повідомити про відсутній або застарілий український дубль як про дефект
   перевірки.

Цей алгоритм діє навіть тоді, коли користувач спілкується з Агентом українською
або іншою мовою.
