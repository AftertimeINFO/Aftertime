# Регламент версій і релізів Model Lab

## 1. Незмінні правила

1. Кожна завершена зміна фіксується окремим Git commit.
2. Кожна знайдена помилка отримує автоматичний regression-тест, який відтворює помилку та проходить після виправлення.
3. Релізний тег створюється лише після успішного повного release gate.
4. Published-моделі та історичні run не переписуються міграціями.
5. Демонстраційні дані не можуть перезаписувати дані користувача під час рестарту.

## 2. Commit-політика

- `feat:` — нова функція;
- `fix:` — виправлення дефекту;
- `test:` — новий або розширений автоматичний тест;
- `docs:` — документація та регламенти;
- `refactor:` — зміна структури без зміни поведінки;
- `release:` — підготовка версії та release evidence.

Функціональне виправлення і його regression-тест зазвичай входять до одного commit, щоб жоден commit не залишав гілку без захисту від повторної появи дефекту.

## 3. Теги

- код продукту: `model-lab-vMAJOR.MINOR.PATCH`;
- release candidate: `model-lab-vMAJOR.MINOR.PATCH-rc.N`;
- версія регламентів: `model-lab-regulations-vMAJOR.MINOR.PATCH`.

Тег регламенту створюється окремо від продуктового тегу, навіть якщо обидва вказують на один перевірений commit.

## 4. Обов’язковий release gate

Release gate запускається командою:

```powershell
./tools/release-test.ps1 -ReleaseTag model-lab-vX.Y.Z-rc.N
```

Gate повинен перевірити:

1. frontend regression-тести;
2. TypeScript production build;
3. `npm audit` без high/critical вразливостей;
4. повний backend test suite у Python 3.13 контейнері;
5. повну міграцію чистої PostgreSQL бази до `head`;
6. застосування міграцій до наявної dev-бази;
7. health API та frontend, відповідь `PONG` від Redis і стан `running` у simulation worker;
8. контракт workspace v2: типізовані порти, observables, event types і monitor templates;
9. відсутність whitespace-помилок у Git diff.

## 5. Реєстрація дефекту

Для кожного дефекту в тесті або changelog фіксуються:

- видима ознака;
- першопричина;
- автоматичний сценарій відтворення;
- очікувана поведінка;
- версія, у якій дефект закрито.

Поточні приклади:

- спроба з’єднати `emission/co2_mass_flow` з `natural_gas/gas_energy_flow` повинна бути відхилена без зміни графа, після чого модель залишається валідною та доступною для запуску;
- недоступна черга симуляції повинна повертати retryable `503`, зберігати run у стані `queue_waiting` і ніколи не маскуватися як `Internal Server Error`;
- release gate повинен зупиняти реліз, якщо Redis не відповідає або simulation worker не працює.
